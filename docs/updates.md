# App updates

Development source supports in-app updates for `com.sogud.bananatv`. Install this new identity separately first; the legacy v0.1.11 application cannot upgrade to it in place. Data, permissions and Home/screen saver selections are not migrated. Future updates keep the new ID and signing certificate.

Open **控制中心 → 检查更新**. Automatic checks run at most once per day while Home is used, with at least one hour between failed automatic attempts. They can be disabled. Downloads start only when selected, show progress and can be cancelled with Back. A failed mirror advances to the next URL; retry restarts the download. Android requires the user to allow Banana TV to install apps and confirm the installation. No Root or silent-install mechanism is included. A firmware that blocks third-party installers may still require ADB.

Changing installer permission may restart the app. Return to **检查更新 → 安装更新**: the downloaded APK is reused and checked again before installation. If Android has reclaimed its cache, download it again.

Downloads are bounded to 512 MiB. Before installation, the app checks size, SHA-256, package name, increasing versionCode, versionName, minSdk and the installed app's exact signer set. A different key, downgrade or invalid file is rejected without uninstalling or clearing data. Signing-key rotation needs a separate migration; do not publish a new signing key through this channel. Settings and media history remain in the same app data directory during a normal Android update.

## Distribution without GitHub

Use a stable HTTPS manifest on an operator-controlled domain and immutable, versioned APK URLs. Put a mainland-accessible object store/CDN first and a second independent host or GitHub last. Metadata and APKs must both have a reachable path without GitHub. A CNAME alone does not establish mainland accessibility; check DNS, manifest, full APK download and TLS on actual mainland networks before announcing support.

Set `app/src/main/assets/update-feeds.json` before building, in priority order:

```json
[
  "https://downloads.example.com/banana-tv/stable/update.json",
  "https://backup.example.com/banana-tv/stable/update.json"
]
```

These are placeholders, not deployed endpoints. The checked-in list is empty because no domestic distribution host has been deployed. After configured feeds fail, the app tries the project's GitHub release API and its `update.json` asset. Legacy releases without that asset offer only a browser link. Failed checks retain the last valid manifest, labelled as a previous check. Cached higher versions are not replaced by an older mirror or GitHub release.

The app accepts up to four feeds and four APK mirrors per manifest. All requests and redirects require HTTPS with normal certificate verification. Update checking sends no app settings, device identifiers or media history; the hosting provider sees normal network request information such as IP address.

## Publish a version

1. Keep `com.sogud.bananatv` and the original release signing key. Increase `versionCode`, set `versionName`, then build and sign the release using the external signing variables in README.
2. Generate metadata from the **final signed APK**. The tool verifies the APK signature and reads its package, versions and minSdk; it never uploads anything:

```sh
python3 tools/make_update_manifest.py /path/to/banana-tv.apk \
  --url https://downloads.example.com/banana-tv/0.1.12/banana-tv.apk \
  --url https://github.com/sogud/banana-tv/releases/download/v0.1.12/banana-tv.apk \
  --output /path/to/release/update.json
```

3. Upload the same APK bytes to every mirror. Download them back and compare their hashes. Keep versioned APK objects immutable with a long cache lifetime.
4. Upload `update.json` **last**, to the stable feed and as a GitHub release asset. Use a short manifest cache lifetime, for example five minutes. Standard and Guard builds need their own feeds; mismatched variants are rejected.
5. Test an upgrade from the previous signed version, including local preferences/history, cancelled download/install, a failed primary mirror and a wrong-signature APK. Verify the television's installer separately from emulator checks.

The manifest schema is generated by the tool: `schemaVersion`, `packageName`, `variant`, `versionCode`, `versionName`, `minSdk`, `size`, `sha256`, `urls`, and optional `notes`. A hash protects against corruption; the installed signing certificate establishes whether the APK belongs to this app. Keep the feed's domain and hosting account under maintainer control.

Media-source configuration is separate from app upgrades: see [source catalog](source-catalog.md). Source-list changes can be published without rebuilding the APK; application code changes require a signed APK.

Android references: [trusted installation sources](https://developer.android.com/reference/android/content/pm/PackageManager#canRequestPackageInstalls()), [FileProvider URI permissions](https://developer.android.com/reference/androidx/core/content/FileProvider).

## Focused emulator check

Build `:app:assembleDebug` with `-PupdateFixture -PupdateFixtureCode=14` and copy the resulting APK to a temporary upgrade path. Then build `:app:assembleDebug :app:assembleDebugAndroidTest` with `-PupdateFixture` (versionCode 13). This uses the separate `com.sogud.bananatv.updatetest` package and the developer's debug certificate, never the owner's app data or release key.

```sh
python3 tools/check_updates.py --server ADB_SERVER --serial emulator-SERIAL \
  --current-apk app/build/outputs/apk/debug/app-debug.apk \
  --upgrade-apk /path/to/fixture-14.apk \
  --test-apk app/build/outputs/apk/androidTest/debug/app-debug-androidTest.apk \
  --output /path/to/check-output
```

Requires the build environment above and OpenSSL. The script uses a temporary localhost TLS certificate, tests failure paths, opens Android's installer, confirms the isolated fixture upgrade and verifies a preference survives. It leaves the fixture packages installed for inspection; they may be removed after inspecting the output. No TV, production package, Home selection or system-package changes are made.
