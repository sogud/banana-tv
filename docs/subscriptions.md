# 影视源接入与订阅配置

**已经安装应用：用手机扫码填写影视配置地址即可，无需重新打包。** 对外订阅沿用 TVBox / CatVod 社区通用 JSON，目标是复用影视仓、TVBox 使用的同一份单配置，不要求改成 Banana TV 专属格式。这里指社区约定，不是正式统一标准；各客户端支持的字段和脚本仍有差别。

自己编译私有版时，可以用 `banana-tv.config.json` 预填地址。它只是开发者的打包配置，不是另一种影视订阅协议。公开构建不提供影视源或直播订阅。

## 先确认地址类型

| 手里的地址或文件 | 应该填在哪里 |
| --- | --- |
| TVBox / CatVod JSON 配置，顶层包含 `sites` | **影视 → 设置 → 来源配置**。一个配置可以包含多个内容来源。 |
| 多线路／仓库索引，顶层包含 `urls` | 当前不能直接导入。先选择其中一个条目，导入该条目指向的、带 `sites` 的配置地址。 |
| 直播 M3U / TVBox TXT 列表 | **影视 → 直播 → 直播订阅**。与点播影视分开配置。 |
| XMLTV / XMLTV.gz 节目单 | 直播订阅中的节目单选项，可留空。 |
| 某个网站的影片页、GitHub 文件浏览页、单个 MP4 / M3U8 视频地址 | 不能作为影视配置地址导入。 |
| 本地 `banana-tv.config.json` | 放在项目根目录供编译读取；不是电视要导入的 TVBox 配置。 |

影视配置地址应通过 HTTP(S) 直接返回 JSON，不要求文件名以 `.json` 结尾。GitHub 的文件浏览页返回 HTML；需要使用文件的原始内容地址，且电视所在网络必须能访问。

## 手机扫码接入

1. 在电视打开 **影视 → 设置 → 来源配置 → 扫码配置来源**。
2. 手机连接与电视相同的局域网，扫描电视上的二维码。
3. 在手机的 **配置地址** 中粘贴你自己的 TVBox / CatVod 配置地址，选择 **保存到电视**。
4. 等待手机提示保存成功。电视会下载并验证配置；失败时保留上一次有效配置。
5. 关闭配置窗口，进入 **电影／剧集／动漫** 等分类或使用 **搜索**。影视默认打开 **最近播放**，首次没有观看记录是正常情况。

二维码页面十分钟后失效；关闭电视上的窗口也会停止服务。打不开时先检查手机与电视是否在同一局域网、路由器是否启用了访客网络或设备隔离，再重新生成二维码。这是影视内的 **扫码配置来源**，与主屏幕控制中心的 **手机配置** 分别用于不同内容。

没有手机时，在 **影视 → 设置 → 来源配置 → 添加来源** 输入同一个配置地址，选择 **添加**。

## 管理多个来源

**来源配置** 管理当前导入的整份订阅；**内容来源** 管理这份订阅里面的网站或接口：

- 在 **影视 → 设置 → 内容来源** 勾选需要的来源，选择 **保存**。启用的来源参与首页、分类和跨源搜索。
- 影片详情保留来源切换；每个来源有自己的线路和选集，不把不同来源的影片 ID 混用。
- 当前一次使用一份影视配置。再次通过 **添加来源** 或扫码导入，会替换当前自定义配置，不会自动把两个订阅合并。需要长期聚合时，先合成一份配置，再使用固定地址分发，见 [维护自己的源](source-catalog.md)。

公共构建的 **内置来源** 为空；想恢复自己的配置，应选择 **自定义来源**。**使用打包订阅** 只在编译时确实预填了影视订阅地址的版本中出现。

## 支持的配置格式

普通用户直接复用已有兼容配置，无需编辑 JSON。自己维护时，配置至少需要一个 `sites` 条目。下面沿用社区字段，不加入 Banana TV 必需扩展；**示例域名不可播放，需替换为你实际维护或有权使用的接口**：

```json
{
  "sites": [
    {
      "key": "my-library",
      "name": "我的片库",
      "type": 1,
      "api": "https://provider.example/api.php/provide/vod/",
      "searchable": 1,
      "quickSearch": 1,
      "filterable": 1
    }
  ]
}
```

把这份文件托管为可直接访问的地址，例如 `https://media.example/sources.json`，再把**文件地址**填到电视。直接填写返回影片 `list` 的采集接口不等于导入整份配置；它应放在 `sites[].api` 中。

社区配置中的常见部分，以及当前 Banana TV 的处理方式：

| 字段或格式 | 当前处理 |
| --- | --- |
| `sites` 与 `key`、`name`、`type`、`api` | 点播来源入口；保留上游字段名和来源 ID。 |
| `searchable` | 控制来源是否参与搜索；`quickSearch`、`filterable` 不提供与其他客户端完全相同的独立开关。 |
| `spider`、站点 `jar` / `ext` | 按来源加载依赖和参数；运行兼容性取决于具体实现。 |
| `parses`、`flags` | 已有解析流程使用；并非所有第三方解析器都兼容。 |
| `lives` | 当前不会从影视配置自动导入直播。将其中的 M3U / TXT 地址另填到 **直播订阅**。 |
| `wallpaper` | 当前不会从影视配置自动设置桌面壁纸；在 **设置 → 壁纸** 单独选择。 |
| `urls` 仓库索引 | 当前只接受其条目指向的实际 `sites` 配置，不提供仓库选择器。 |
| 客户端专有 UI、播放器、网络设置等字段 | 不承诺逐项实现，导入配置不等于这些设置生效。 |

单份来源配置与 `urls` 仓库索引是两层结构，不能互相代替。字段命名可参考 [TVBox 配置字段示例](https://github.com/riowang88/TVBoxOS#配置格式参考)。这只是格式参考，不是内置或推荐的内容订阅；接入其他客户端时也要单独确认能否播放。

| 来源实现 | 接入条件 |
| --- | --- |
| XML 接口（type 0）、JSON 接口（type 1 / 4） | 通过 `sites` 声明接口；不需要额外运行组件，返回格式仍需兼容。 |
| Java 爬虫（type 3，`csp_`） | 配置须提供相应 JAR 与扩展参数；仅有入口地址不足以运行。 |
| JavaScript / Python 脚本 | 需要相应脚本及兼容运行组件，见 [运行组件](media-center.md#runtime-components)。 |

TVBox 配置格式相同，不代表所有脚本都兼容。Node.js 来源、加密配置／仓库格式、需要登录或 DRM 的服务不属于当前支持范围。请导入可信配置：JAR 和脚本会使用应用的访问权限执行。

## 更新配置与播放失败

自定义配置保存在电视本机。打开影视时先使用已有配置；默认每天按需检查订阅更新，下载成功后在下次进入影视时应用，不替换正在搜索或播放的来源。检查失败时保留已有配置，后续进入可重试。**来源配置 → 更新配置** 可以立即更新；**自动更新** 可以关闭检查。保留同一个订阅地址即可获取维护者的后续更新，不必每次重新扫码。

| 现象 | 先检查什么 |
| --- | --- |
| 提示配置无效 | 地址是否直接返回 JSON；顶层是否有非空 `sites`；各条目的 `key` 是否唯一，`api` 是否填写。 |
| 下载失败或超时 | 用电视所在网络检查配置地址；浏览器可访问不代表电视可访问，也要检查令牌和 HTTPS 证书。 |
| 导入成功但片库为空 | 先切换分类或搜索；再检查 **内容来源** 是否启用，以及相应来源接口是否可用。 |
| 提示缺少运行组件／不支持来源类型 | 按提示核对脚本运行组件和来源实现；更换订阅地址不会自动补齐组件。 |
| 海报能显示，影片不能播放 | 封面与视频通常来自不同地址。检查其他线路或来源；配置下载成功不等于视频链路可用。 |
| 换源后时间点略有不同 | 确认是同一集、同一剪辑版本；片头和版本差异可能导致相同进度对应不同画面。 |

**设置 → 优先选择较快来源** 会参考有限候选的测速和本机播放记录，不保证每次都是最快线路。播放失败时会提示更换来源，由你选择确认；同一集可识别时保留进度，详见 [选源与播放恢复](media-center.md#source-selection-and-recovery)。缓存保存配置和部分片库数据，不会把全部影片下载到电视，播放仍需要网络。

## 编译时预填订阅

把配置保存为项目根目录的 **`banana-tv.config.json`**。编译时会自动读取，影视与直播使用同一个文件。文件不存在时，安装包不内置订阅，用户仍可在应用中手动或扫码填写。

### 生成打包配置

空白项表示不预设该类订阅。直播最多支持六个地址，每行一个。

### 打包配置文件格式

可以复制根目录的 `banana-tv.config.example.json`，另存为 `banana-tv.config.json` 后填写：

```json
{
  "media": {
    "subscription": ""
  },
  "live": {
    "subscriptions": [],
    "epg": ""
  }
}
```

| 字段 | 用途 |
| --- | --- |
| `media.subscription` | TVBox / CatVod 配置订阅地址。不是单个影片的视频地址。 |
| `live.subscriptions` | HTTP(S) M3U 或标准 TVBox TXT 直播列表，最多六个，自动合并同名频道。 |
| `live.epg` | 可选 XMLTV 或 gzip 节目单地址。留空时使用订阅声明的节目单。 |

例如，只预填影视订阅时，将 `media.subscription` 改为你实际的 `sources.json` 文件地址，`live.subscriptions` 保持 `[]`，`live.epg` 保持空字符串。不要把上面的 `sites` 对象直接复制到这个文件里。

地址必须使用 HTTP 或 HTTPS。拼写错误、错误类型和无效地址会使打包失败；错误信息不回显地址内容。

### 编译

```sh
./gradlew --no-daemon :app:assembleDebug
```

也可以从仓库外读取配置：

```sh
./gradlew --no-daemon :app:assembleDebug \
  -PsubscriptionsConfig=/absolute/path/to/banana-tv.config.json
```

指定了不存在的文件时，构建会报错，不会悄悄改成空白包。公开构建可以明确选择空白示例，避免本地私有配置影响产物：

```sh
./gradlew --no-daemon :app:assembleDebug \
  -PsubscriptionsConfig=banana-tv.config.example.json
```

签名与正式构建要求见 [安装与恢复](install.md)。完整离线影视目录仍可通过 [维护源目录](source-catalog.md#public-and-private-builds) 中的 `privateMediaSources` 参数传入；它不能与 `media.subscription` 同时配置。

### 应用如何使用

1. 首次打开影视时，若没有保存过用户配置，会尝试读取打包的影视订阅；失败时仍可手动或扫码填写，稍后重试。
2. 首次打开直播时，读取打包地址并下载频道列表。没有网络或订阅失效时会保留已有缓存。
3. 已有运行时配置优先。覆盖安装和修改打包文件不会静默替换用户已经保存的订阅。
4. 要重新使用打包地址，选择 **来源配置／直播订阅 → 使用打包订阅**。

### 私有构建与公开构建

根目录配置已加入 Git 忽略规则，示例文件保持空白。构建不会把实际地址写回源码。

::: warning 私有 APK 也能被读取
内置配置会进入 APK，其他人可以提取其中的地址。包含个人订阅或访问令牌的 APK 不应公开分发；公开发布前使用空白配置重新构建。
:::

订阅文件只提供入口，不包含视频，也不会替上游提供加速或稳定性保证。请使用自己有权访问的内容。
